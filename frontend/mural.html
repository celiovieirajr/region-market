⚡ v1.1.0 — Cache inteligente de preços

Concluído hoje

Respostas de preço agora podem vir de um cache estruturado por produto (nome, preço, loja) em vez de raspar o site ao vivo toda vez — muito mais rápido quando o cache está quente, com fallback automático e transparente pra busca em tempo real quando não está. Corrigido também um bug de login que não mostrava erro com senha errada.

⚡ Cache de preços (novo)

  • Nova tabela de produtos em cache (nome, preço, categoria, loja) alimentada por um job automático a cada 30min, com espaçamento entre buscas pra não sobrecarregar os sites
  • Configurável por mercado em Configurações: liga/desliga cache, ajusta validade (TTL em horas), e botão "Atualizar agora" pra forçar refresh manual
  • Habilitado hoje pra Supermercados Rondon, Atacadão e Pão de Açúcar (Amigão e Assaí não têm busca por produto, ficam de fora)
  • Guarda de segurança: conteúdo que parece página de verificação anti-robô nunca é salvo no cache — se acontecer, o sistema cai automaticamente na busca ao vivo pra aquele produto/loja, sem mostrar erro pro usuário
  • Cache ausente ou vencido é sempre coberto pela busca em tempo real de hoje — nada quebra se o cache não estiver disponível

🚀 v1.0.0 — Lançamento inicial

Base do sistema

Resumo de tudo que foi construído: chat com IA (DeepSeek), login/cadastro com JWT, pesquisa de preços em tempo real em mercados de Araçatuba/SP via navegador headless, e painéis de administração.

🔐 Autenticação e contas

  • Login JWT completo (usuário/senha, BCrypt, token com expiração de 24h)
  • Cadastro grátis auto-serviço direto do chat público — visitante digita, é obrigado a criar conta antes da IA responder
  • Roles ADMIN e USER — só admin vê Configurações e Mural
  • Usuário admin/admin123 semeado no boot

💬 Chat com IA

  • Integração com DeepSeek (API compatível OpenAI) para respostas em português
  • Histórico de conversa persistido por usuário, com opção de limpar contexto (com modal de confirmação)
  • Cronômetro ao vivo durante o processamento ("IA está digitando... Xs"), com tempo final registrado em cada resposta
  • Tema claro/escuro em todas as páginas, com preferência salva por navegador

🛒 Pesquisa de preços em tempo real

  • Usuário define sua cidade no perfil (sem precisar digitar toda vez)
  • Admin cadastra sites por cidade em Configurações, com busca dinâmica por produto via placeholder {termo}
  • Navegador headless real (Playwright/Chromium) lê o preço já renderizado — funciona em sites React/Angular que só mostram preço via JS
  • 5 mercados de Araçatuba/SP cadastrados: Supermercados Rondon, Atacadão (via API GraphQL pública), Pão de Açúcar, Amigão e Assaí (estes dois últimos só como referência, sem busca por produto)
  • Resposta da IA sempre separada por loja, ignorando mercados sem resultado (sem poluir com "não encontrado")
  • Espera adaptativa (aguarda o conteúdo da página estabilizar) em vez de tempo fixo — mais rápido e mais confiável

🏗️ Arquitetura

  • Backend: Java 21, Spring Boot 3.3, Maven, Spring Security, Spring Data JPA, Liquibase, H2
  • Frontend: HTML/CSS/JS puro + Tailwind, MVC (model/view/controller), servido separado do backend
  • Frontend e backend rodam em servidores/portas diferentes (5500 e 8080), prontos pra deploy separado
  • CORS liberado para comunicação entre os dois

⚠️ Limitações conhecidas

  • Amigão e Assaí não têm busca dinâmica por produto (sites institucionais/exigem sessão) — ficam como referência estática
  • Pão de Açúcar pode sofrer bloqueio anti-bot intermitente sob rajada de requisições — quando acontece, o produto fica sem cache naquela rodada e a busca cai pro modo ao vivo normalmente (não é tratado como erro)
  • H2 em arquivo é só para desenvolvimento — produção precisa de Postgres/MySQL gerenciado
  • Playwright roda numa única thread — buscas concorrentes esperam na fila (sem paralelismo ainda)
  • Não pronto para Vercel (serverless) — precisa de um host com processo persistente (Railway, Render, VM/Docker)
